# プロダクト概要 (uma-family-tree)

JV-Link (JRA-VAN Data Lab.) で取得した競走馬データから血統を **DAG (有向非巡回グラフ)** として構築し、
[3d-force-graph](https://github.com/vasturiano/3d-force-graph) を用いて **3D フォースダイレクテッドグラフ**として可視化する Web ビューア。

## コアコンセプト

- 血統は本来「世代ごとに2倍になる二分木」だが、インブリード (クロス) により同一祖先が複数箇所に現れるため、
  厳密には **DAG** になる。本プロダクトは木ではなく DAG として扱い、同一祖先を **1ノードに集約**する。
  これにより 3D 表示の意味 (クロスの可視化) が生まれる。
- 任意の馬を **中心 (フォーカス)** に据え、**祖先方向・子孫方向の双方向**を辿れる。
- ノードをタップすると、その馬が新しい中心になり再センタリングされる
  (例: ゴルシ中心 → 母父メジロマックイーンをタップ → マックイーン中心)。

## 利用形態

- JV-Link を使ったリアルタイム取得は **行わない**。
- 別マシン (Windows) でダウンロード済みの生データを **事前加工**し、Cloudflare D1 に投入して配信する。
- Svelte アプリは組み立て処理を持たず、**ビューアに徹する** (API 経由でデータを読んで描画するだけ)。
  祖先/子孫の探索は D1 上の再帰 CTE で行う。

## 技術スタック

- ビューア: SvelteKit + 3d-force-graph (Three.js ベース)
- デプロイ: Cloudflare Pages + Pages Functions (`/api/*`)
- データ配信: **Cloudflare D1 (SQLite)**。API 経由で取得
  (初期は R2 + 静的 JSON を想定していたが、検索15MB問題・15万ファイル問題を解消するため D1 へ移行)
- 加工パイプライン: Python (JV-Link SDK に Python サンプル・構造体定義があるため)
- 構成: モノレポ (加工パイプラインとビューアを同一リポジトリで管理)

> 運用・デプロイ・無料枠の注意は `.kiro/steering/operations.md`、データモデルは `docs/data-model.md`、
> 機能は `docs/features.md` を参照。

## スコープ外 / 非目標

- JV-Link のリアルタイム連携
- フロントエンドでの血統組み立て・重い計算
- 数万ノード規模を一度に描画すること (表示範囲を絞る戦略で回避)
- 全部盛りモード (主要始祖の全子孫を一括表示) は **対象外** (優先度低)

## 設計判断・前提 (今後の実装で守る)

これまでの検討で確定した方針。変更する場合はここを更新する。

### データ・キー
- **ノード一意キー = HansyokuNum** (`node_id = "H" + 繁殖登録番号`)。血統リンクは繁殖番号で張られ、
  KettoNum (血統登録番号) は競走馬にしか無い (輸入種牡馬等は持たない) ため。KettoNum は検索/URL 共有の
  補助キーとしてノードに併記。URL 共有は `/?horse={node_id}`。
- **系統 (keitoId)** は BT の系統代表馬にのみ存在。各馬へは**父方をさかのぼって最初に見つかる KeitoId を継承**
  (付与率 約88.5%)。主要系統に丸めて色分けする。

### データの正確性 (免責の根拠)
- 加工パイプラインの検証は**ごく一部**しかできていない。8桁繁殖番号のオフセット確定・レコード解釈・系統丸めなど、
  加工に起因する誤り・欠落がありうる。**血統の正確性は保証しない**。
- そのため viewer には**免責事項**と**データ基準時点** (meta の `data_timestamp`) の明示が**必須要件**。

### 表示破綻の回避 (三本柱)
- **N世代ウィンドウ**: 通常は祖先5代 + 子孫1代。子表示モードは祖先0 + 子孫1〜3代。
- **代表的な子**: 中心の直仔が閾値 (40) 超なら代表に絞る。「すべて表示」で解除可。
- **各親の fanout**: 子孫を2代以上辿るとき、各親から**獲得賞金上位8頭**のみ辿る (孫以降の爆発を防ぐ)。
- 世代スイッチャーは、データ上たどれる世代 (`maxDescDepth`) までに制限する。

### 代表子孫の優先指標 = 獲得賞金
- 「活躍した子孫を優先表示」は、**UM の平地本賞金累計・総合1着回数**で近似する
  (獲得賞金の多い順 → 勝利数 → 子孫を持つ子 → 生年)。
- **保有データ (UM/HN/SK/BT) には「重賞勝ち」フラグが無い**。厳密な重賞/G1 勝ち判定が必要になったら、
  **RA (レース詳細の GradeCD) + SE (馬毎レース情報の確定着順)** の追加取得・加工が必要 (将来対応。データ量大)。

### UI 方針
- **スマホ中心設計**。PC マウス/ホバーは前提にしない (3d-force-graph の showNavInfo は off)。
- 中心から5世代まで常時ラベル。ノードタップ = 詳細パネル表示 → 「中心にする」で再センタリング。
- データが無い馬は「中心にする」を無効化し、404 で操作不能にしない。
